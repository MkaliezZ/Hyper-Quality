# 资源账与BOM制度

> 0.3.0适用边界：下文实测强度与产品门槛用于产品验收。PRD按[方案制度](09-开发方案评审.md)评设计质量，原始文档可支撑0—4；实证成熟度、执行准备和资源资格另列。未知价格/用量不自动扣设计分，漏成本构成/估算方法仍是缺陷。

用户已明确：先建立严格制度，实际额度后填。所有默认额度为null；0表示明确不能消耗，含义不同。

开发方案另按validation/development/operation/exit标phase，保留全方案账及单个请求里程碑账。预算scope必须等于该里程碑；开发/验证成本为one_off，重复次数写quantity。范围不同的成本不直接比较，不能用单里程碑额度默认放行整体路线；具体见09-开发方案评审.md。

## 两本账

**BOM**回答交付单位由哪些投入组成、数量和单价如何、什么依据；**资源账**回答当前窗口要占用多少现金、负责人小时、团队小时、token和关系使用。BOM是投入组成，资源账是其在交付量与时间窗口下的汇总。

每条成本记录：类别、计费单位、one_off/monthly/per_unit/sunk、数量low/base/high、每计费单位各资源消耗low/base/high、estimated/quoted/measured/unknown、来源、报价日期/假设、责任人（说明中填写）及零值原因。不能用“软件没有物料”把人工交付和支持成本归零。

## 必须覆盖的九类

| 类别 | 软件/Agent/Skill | 课程/硬件 |

| infrastructure | 服务器、存储、网络、备份、监测 | 课堂设备、共享基础设施 |
| tool_licenses | API、工具、软件、素材许可 | 教学软件、设备软件和内容许可 |
| human_delivery | 配置、人工接管、研究、质检 | 备课、授课、助教、装配 |
| support_rework | 客服、故障、返工、退款处理 | 课后辅导、补课、维修与退换 |
| acquisition | 获客、渠道、试用、销售 | 招生、机构沟通、样机 |
| materials_equipment | 适用的设备折算/租赁 | 采购物料、耗材、加工、物流、良率 |

## 核算公式

窗口成本 = 一次性成本 + 月固定成本 × 月数 + 单位交付成本 × 月交付量 × 月数。

每条资源量 = 计费数量 × 每计费单位资源消耗 × 适用窗口倍率。现金API费用已进cash，tokens仅保留容量约束，不再折钱相加。负责人无现金支出的工时可以cash为0，但owner_hours不能因此为0。

单位现金贡献 = 单价 − 单位变动现金成本。盈亏平衡交付量 = 向上取整（窗口固定现金 / 正的单位现金贡献）；贡献不为正时不输出虚假的盈亏平衡点。该计算是现金贡献口径，**不是净利润**。应计收入、回款延期、退款概率、税费、折旧及机会成本需要依据当前项目单列。

low/base/high描述输入用量与单价的有序区间。另算**高单位成本+高固定成本+低售价+低销量**压力现金余额，避免把高成本总与高收入绑定。容量不足或单位范围变化需要新模型，不能把线性外推当规模化实证。

沉没成本以sunk保留，但不纳入未来增量预算。历史资产确能节省未来资源时，计节省的未来劳动，不能按过去花费直接给资产加分。储备金和已记费用也不能重复计算。历史储备不是第二笔成本。

## 关系资源

`relationship_uses`只是容量计数。每次真实动用仍需关系台账：对象/角色、拟请求事项、引荐人、维护工时、信任损耗或承诺风险、可替代渠道、是否已获本次授权、兑现/回访义务。关系不统一折成人民币，也不把用户认识某人视为可以调用其资源。

第一版不会自动联系任何人。即使所有数值在额度内，输出仍为“额度内待负责人决定”。关键关系、对外承诺及不可逆投入由用户决定；既有明确授权在范围内有效。

## 分配决策卡

填写：请求阶段、时间窗口、low/base/high五类资源、最坏损失、当前瓶颈、依赖对象、可缩减项、替代投入、下一里程碑、成功线、停止线、责任人。没有完整现金流与资源口径，不承诺ROI或利润。

课程特别记录班额、实际出勤、教师/助教比例、课前调试、每位学员介入分钟、课后辅导、设备共用和补课。硬件特别记录含税采购、最低起订量、加工损耗、良率、包装物流、质保和维修。数字会随班额/批量变化，不默认规模越大越便宜。
